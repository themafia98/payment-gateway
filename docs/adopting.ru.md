# Практические вопросы

> English version: [adopting.md](./adopting.md)

То, о чём команда спрашивает до того, как ставить чекаут к себе: сколько весит, рисуется ли на
сервере, что скажет скринридеру, на каком языке говорит и какие браузеры отсекает.

## Сколько весит

Собрано, минифицировано, gzip — на момент этого коммита:

| Пакет                           | gzip       |
| ------------------------------- | ---------- |
| `@checkout-kit/core`            | 7.2 кБ     |
| `@checkout-kit/runtime-browser` | 3.7 кБ     |
| `@checkout-kit/react`           | 1.1 кБ     |
| `@checkout-kit/ui` (JS)         | 1.2 кБ     |
| `@checkout-kit/ui/styles.css`   | 1.4 кБ     |
| плагин                          | 1.3–2.6 кБ |

То есть чекаут с одним провайдером — примерно 14 кБ JavaScript плюс 1.4 кБ CSS, каждый
следующий провайдер добавляет около 1.5 кБ. Рантайм-зависимостей нет нигде: у всех пакетов
`dependencies` пустые, а то, что им нужно друг от друга и от React, — peer-зависимости.

Держится это на двух вещах, и обе стоит беречь:

- **Плагины загружаются, а не импортируются.** `load: () => import('@checkout-kit/provider-x')`
  кладёт каждый в свой чанк, и покупатель скачивает того провайдера, которым платит. `eager:
true` нужен только провайдеру по умолчанию.
- **Набор не рисует QR и не тащит иконки.** Провайдер, который использует QR, возвращает URL
  картинки. Именно поэтому здесь нет кодировщика.

## Рендер на сервере

В `@checkout-kit/core` нет DOM, и `npm run purity` роняет сборку, если он туда попадёт.
`@checkout-kit/react` читает движок через `useSyncExternalStore` с серверным снапшотом,
поэтому компонент, показывающий фазу или сумму, спокойно рисуется на сервере.

Браузерных мест ровно два, и оба про это честно говорят:

- **`createBrowserRuntime()`** читает `window.location`, чтобы собрать URL возврата. Создавайте
  движок в браузере — в модуле, который импортирует только клиент, или внутри эффекта.
- **`<PaymentActionHost/>`** работает в эффекте, поэтому на сервере это пустой `<div>`, и
  ничего не запускается.

Гидрировать нечего: платёж в процессе живёт в session storage, а `hydrate()` подхватывает его
после редиректа. Зовите его в лоадере роута, а не в эффекте — см.
[Архитектуру](./architecture.ru.md).

## Скринридеры и клавиатура

Что набор рисует сам:

- У фреймов есть заголовок. Ставьте тот, который покупатель узнает —
  `redirect: { frameTitle: () => 'Аутентификация банка' }`: именно его читает скринридер, когда
  фокус входит на страницу банка.
- Раннер показанного платежа помечает кнопку копирования вежливым live-регионом, чтобы
  «Скопировано» было озвучено, а у картинки QR есть alt, который вы задаёте.
- Всё — настоящий HTML: кнопка это `<button>`, ссылка это `<a>`. Единственное место, где
  `@checkout-kit/ui` использует ARIA, — вкладки провайдеров (`tablist`/`tab`/`aria-selected`) и
  текст ошибки (`role="alert"`).

Что остаётся вам, потому что больше некому:

- **Озвучивать состояние платежа.** Фаза лежит в снапшоте; положить её в
  `aria-live="polite"` — несколько строк, и это разница между рабочим чекаутом и молчащим. За
  вас этого не сделать: набор не владеет вашей вёрсткой.
- **Осознанно двигать фокус.** Когда открывается действие или платёж завершается, решите, куда
  уходит фокус.
- **Ошибка рядом с полем.** `PaymentError.message` написан для покупателя; показывайте его
  там, куда покупатель смотрит, с `role="alert"`.

В демо сделаны два последних пункта: ошибки идут через `ErrorText` с `role="alert"`, ожидание —
`role="status"`. Озвучивание каждой смены фазы оставлено хосту: только он знает, где в его
вёрстке этому место.

## Языки

Любую строку, которую набор выводит на экран, можно заменить:

```ts
createBrowserRuntime({
  returnPath: '/payment/return',
  redirect: { frameTitle: () => t('checkout.bankAuthentication') },
  collectFields: { frameTitle: () => t('checkout.cardDetails') },
  display: {
    text: {
      copy: t('common.copy'),
      copied: t('common.copied'),
      openApp: t('checkout.openBankApp'),
    },
  },
})
```

С сообщениями, которые приходят от платежа, всё иначе. `PaymentError.message` — это слова
провайдера, обычно эмитента, и переводить их не ваше дело: «на карте недостаточно средств»
сказал банк, и правка формулировки может поменять смысл.

Если переводы всё-таки нужны, ветвитесь по `PaymentError.code`, а на незнакомый код
показывайте `message`. Ради этого `code` и существует, и поэтому ошибки здесь — данные, а не
классы исключений.

Деньги за вас тоже никто не форматирует. `intent.amount` — в минорных единицах,
`intent.currency` — код ISO; это всё, что нужно `Intl.NumberFormat`.

## Браузеры

Только ESM, без CommonJS-сборки. Пакеты уезжают в том синтаксисе, в котором написаны, так что
насколько глубоко их компилировать — решает ваш бандлер.

Того, что набору нужно в рантайме, немного, и это стоит знать точно:

| Что                       | Где                | С какой версии                       |
| ------------------------- | ------------------ | ------------------------------------ |
| `crypto.randomUUID`       | id по умолчанию    | Chrome 92, Firefox 95, Safari 15.4   |
| `AbortSignal.any`         | гонка действия     | Chrome 116, Firefox 124, Safari 17.4 |
| `Element.replaceChildren` | освобождение точки | Chrome 86, Firefox 78, Safari 14     |

`AbortSignal.any` новее остальных на два года, поэтому движок берёт его, только если он есть, а
иначе вешает слушатели сам: телефон на две версии позади всё ещё покупает. Тогда практический
пол — `crypto.randomUUID`, и даже его можно заменить:
`createCheckout({ uuid: () => myOwnId() })`. Ему ещё нужен secure context, который у платёжной
страницы и так есть.

Если найдёте что-то ещё, что поднимает этот пол, — это баг, о нём стоит сообщить.

Два поведения браузеров стоит держать в голове, потому что они бьют по реальным платежам:

- **Блокировка сторонних кук** ломает часть банковских страниц внутри iframe. Если фрейм
  челленджа в Safari остаётся пустым, выполняйте это действие во всём окне:
  `runPendingAction({ surface: 'top' })`. Плагин при этом не меняется.
- **Session storage** — то, что переживает полностраничный редирект. В приватном окне он
  работает, при полностью запрещённых данных сайта — нет, и `hydrate()` вернёт `null`. Поэтому
  платёж всегда можно прочитать у вашего API по id.

## Чего нет

- **Нет CommonJS.** `instanceof` между двумя копиями dual-класса врёт, а платёжная библиотека —
  плохое место для этого. Node 22 умеет `require()` для ESM.
- **Нет React ниже 19.** React-пакет достаточно тонкий, чтобы переписать его под другой
  фреймворк: это один `useSyncExternalStore` и один эффект.
- **Нет перевода сообщений провайдера** — см. выше.
- **Нет офлайна.** Платёж — это разговор с сервером.
