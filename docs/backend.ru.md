# Бэкенд, с которым говорит плагин

> English version: [backend.md](./backend.md)

Всё в этом репозитории работает в браузере. Для демо это осознанно — и это единственное, что
нельзя перенести в продакшен как есть: у плагина нет секретов, поэтому напрямую с провайдером
он говорить не может. Он говорит с вашим API, а ваш API — с провайдером.

```text
браузер: плагин  →  ваш API  →  API провайдера
```

Эта страница — про правую половину стрелки. Она короткая, потому что контракт плагина
короткий.

## Почему не напрямую из браузера

Три причины, в порядке скорости наступления последствий:

1. **Ключ.** `sk_...` у Stripe, `x-api-key` у Adyen, `userName`/`password` у банка. Всё, что
   может отправить браузер, может прочитать и отправить кто угодно.
2. **Истина.** Браузер сообщает, где он был, а не что произошло. `?status=success` в URL
   возврата пишет тот, кто пишет URL.
3. **CORS.** Большинство API провайдеров браузеру вообще не отвечают, и это не случайность.

## Четыре эндпоинта

Плагину нужен один и тот же небольшой набор, как бы ни выглядел провайдер внутри.

| Метод плагина  | Ваш эндпоинт                 | Что делает                          |
| -------------- | ---------------------------- | ----------------------------------- |
| `createIntent` | `POST /payments`             | начинает платёж, возвращает его id  |
| `confirm`      | `POST /payments/:id/confirm` | отправляет инструмент, отдаёт исход |
| `resume`       | `POST /payments/:id/resume`  | принимает evidence, отдаёт исход    |
| `getIntent`    | `GET /payments/:id`          | текущее состояние, авторитетное     |
| `cancel`       | `POST /payments/:id/cancel`  | необязательный                      |

Главный здесь — `getIntent`. На него движок опирается, когда ответ неокончательный, его
дёргает опрос, и на него же попадает покупатель, перезагрузивший страницу.

## Что наружу не отдаётся

Возвращайте только то, что чекаут обязан отрисовать:

- сумму, валюту, статус;
- сообщение эмитента об отказе — его словами;
- следующее действие, если провайдер его попросил.

Никогда не возвращайте сырой ответ провайдера, свои ключи, номер карты и вообще всё, чего вы
не хотите видеть в памяти браузера. Последнее проверяется контрактным набором для каждого
плагина здесь: он платит картой и потом обходит весь возвращённый объект в поисках её номера.

## Пример: карточный процессор

Express, один провайдер, без лишних мнений. Плагин зовёт это; в браузере не остаётся ничего.

```js
import express from 'express'
import Stripe from 'stripe'

const app = express()
app.use(express.json())

// Ключ живёт здесь и больше нигде.
const stripe = new Stripe(process.env.STRIPE_SECRET_KEY)

const toPayment = (intent) => ({
  id: intent.id,
  amount: intent.amount,
  currency: intent.currency.toUpperCase(),
  status: toStatus(intent.status),
  // Действие, которое плагин превратит в PaymentAction.
  nextAction: intent.next_action ?? null,
  error: intent.last_payment_error
    ? { code: intent.last_payment_error.code, message: intent.last_payment_error.message }
    : null,
})

app.post('/payments', async (req, res) => {
  // Цена берётся из вашего каталога, а не из браузера. Клиент, который может назвать сумму
  // сам, рано или поздно назовёт 1.
  const plan = await plans.byId(req.body.planId)

  const intent = await stripe.paymentIntents.create(
    { amount: plan.amount, currency: plan.currency, automatic_payment_methods: { enabled: true } },
    // Пробрасывается от плагина: двойной клик не должен списать дважды.
    { idempotencyKey: req.get('Idempotency-Key') },
  )

  res.status(201).json(toPayment(intent))
})

app.post('/payments/:id/confirm', async (req, res) => {
  const intent = await stripe.paymentIntents.confirm(
    req.params.id,
    { payment_method_data: toPaymentMethod(req.body.instrument), return_url: req.body.returnUrl },
    { idempotencyKey: req.get('Idempotency-Key') },
  )

  res.json(toPayment(intent))
})

app.post('/payments/:id/resume', async (req, res) => {
  // Браузер вернулся из банка. Его слова — подсказка; ответ вот здесь.
  const intent = await stripe.paymentIntents.retrieve(req.params.id)

  res.json(toPayment(intent))
})

app.get('/payments/:id', async (req, res) => {
  res.json(toPayment(await stripe.paymentIntents.retrieve(req.params.id)))
})
```

Обратите внимание, чего `resume` не делает: он не читает `req.body.evidence.params.status`.
Evidence говорит, _какой_ платёж вернулся, а что с ним стало — говорит провайдер.

## Правила, которые важны

**Сумма берётся из вашего каталога.** Плагин присылает `planId`, а не цену.

**Пробрасывайте ключ идемпотентности.** Плагин генерирует его на попытку и шлёт во всех
вызовах этой попытки. Передайте его провайдеру — именно это делает повтор безопасным.

**Проверяйте, кто спрашивает.** Эти эндпоинты двигают деньги. Им нужна та же проверка сессии
или токена, что и остальному API, и платёж должен принадлежать тому, кто про него спрашивает.

**Решают вебхуки, странице сообщает опрос.** Провайдер позовёт ваш вебхук, когда асинхронный
платёж досеттлится, — это событие вы и сохраняете. Страница чекаута узнаёт об этом потому,
что `getIntent` начинает отдавать новый статус. Ни плагину, ни движку знать про вебхуки не
нужно.

**Возвращайте сообщение эмитента.** «На карте недостаточно средств» — это то, что покупателю
нужно услышать. «Платёж не прошёл» отправляет его в вашу поддержку вместо его банка.

## Для хостед-страницы, полей, кошелька и перевода

Те же четыре эндпоинта плюс по одному дополнению:

- **Хостед-страница** — зарегистрируйте заказ, верните URL и подписанные параметры. На
  возврате игнорируйте query string и перечитайте заказ.
- **Хостед-поля** — обменяйте токен на списание. Токен приходит из фрейма провайдера, а
  деньгами его делает ваш сервер.
- **Кошелёк** — payload кошелька уходит провайдеру с вашего сервера. Для Apple Pay нужен ещё
  и эндпоинт валидации мерчанта, который серверный по определению.
- **Мгновенный перевод** — запросите у провайдера код, верните его и дайте движку опрашивать
  `getIntent`, пока вебхук не пометит платёж оплаченным.

## Что вместо этого делает репозиторий

У демо сервера нет. Мок-бэкенд на MSW отвечает сразу в форме провайдера, поэтому плагины
работают целиком без сервера. Везде, где настоящая интеграция звала бы ваш API, демо зовёт
мок — код плагина при этом одинаковый, и поэтому он остаётся полезным примером, несмотря на
недостающую половину.
