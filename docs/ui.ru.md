# UI-кит

> English version: [ui.md](./ui.md)

`@checkout-kit/ui` — это видимая половина чекаута: поля, куда покупатель вводит карту,
экраны, через которые проходит платёж, и токены, благодаря которым всё это выглядит вашим
продуктом, а не библиотекой.

Обычный CSS и обычный React. Ни фреймворка, ни CSS-in-JS, ни пакета иконок, ни единой
рантайм-зависимости.

```tsx
import '@checkout-kit/ui/styles.css'
```

Дальше повесьте `ck-root` на обёртку — или возьмите `CheckoutRoot`, который заодно несёт
тему и платформу:

```tsx
import { CheckoutRoot } from '@checkout-kit/react'

;<CheckoutRoot theme="auto">…</CheckoutRoot>
```

Всё скоупится под этот элемент и лежит в каскадном слое `checkout`, так что ваш CSS
выигрывает без борьбы за специфичность. Если вы тоже используете слои — скажите, где наш:

```css
@layer theme, base, components, checkout, utilities;
```

С Tailwind это значит импортировать его по частям, чтобы кит оказался после preflight —
который иначе сбросит нарисованные им кнопки — и до утилит:

```css
@layer theme, base, components, checkout, utilities;
@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/preflight.css' layer(base);
@import '@checkout-kit/ui/styles.css';
@import 'tailwindcss/utilities.css' layer(utilities);
```

## Темизация

Три яруса переменных. Обычно вы трогаете один.

**Перебрендировать всё** — сдвиньте акцент. Hover, нажатие, подложка и кольцо фокуса
выводятся из него, поэтому едут вместе и не расходятся:

```css
.ck-root {
  --ck-p-accent-500: #0a7;
}
```

**Поменять одну вещь** — задайте её семантический токен:

```css
.ck-root {
  --ck-radius: 8px;
  --ck-control-height: 3rem;
  --ck-font: 'Inter', system-ui, sans-serif;
}
```

Семантику читают сами правила: `--ck-accent`, `--ck-surface{,-raised,-sunken}`,
`--ck-border{,-strong}`, `--ck-text{,-muted,-subtle}`, `--ck-danger`, `--ck-success`, плюс
шкалы отступов (`--ck-space-1…12`), кеглей (`--ck-font-size-xs…2xl`), радиусов, высот
контролов, фокуса и анимации. Ярус примитивов под ней (`--ck-p-*`) — это сырые рампы.

**Светлая и тёмная.** По умолчанию тёмная. `data-ck-theme="light"` — светлая,
`data-ck-theme="auto"` — как в системе. Переопределяется только семантика, поэтому светлая
тема — это тот же бренд, а не второй.

```html
<div class="ck-root" data-ck-theme="auto">…</div>
```

**Анимация, контраст и тач** сделаны теми же токенами: один блок `prefers-reduced-motion`
обнуляет все длительности, потому что ни одно правило не хардкодит их; `prefers-contrast:
more` усиливает границы и кольцо фокуса; `pointer: coarse` поднимает минимальную цель до
48px.

**Конвенции платформы.** iPhone и Android расходятся в шрифте, радиусе скругления и в том,
как выглядит нажатие, а из CSS не видно, что именно под ним. `CheckoutRoot` это определяет;
без React зовите `applyPlatform(root)` из `@checkout-kit/runtime-browser` один раз на старте.
`platform="ios"` фиксирует значение, а без атрибута всё падает в десктопные значения.

Всё остальное — тач, hover, цветовая схема, контраст, анимация — остаётся media-запросами,
потому что это браузер знает сам.

**Раскладка меряется по контейнеру, а не по окну.** `.ck-root` — контейнер, и все решения о
раскладке сделаны container-запросами. Один и тот же чекаут рисуется на всю страницу, в
360px WebView и внутри iframe мерчанта неизвестной ширины — вьюпорт в двух случаях из трёх
врёт.

## Компоненты

**Форма.** Главный — `Field`. Он даёт контролу id, направляет на него label и называет
подсказку и ошибку в `aria-describedby`. Через него проходит каждый инпут кита — поэтому ни
одному экрану не нужно об этом помнить.

```tsx
<Field label="Email" hint="Куда придёт чек" error={errors.email?.message} required>
  {(control) => <Input {...control} type="email" autoComplete="email" />}
</Field>
```

`FieldGroup` — это `<fieldset>` для полей, которые вместе задают один вопрос, например адрес
плательщика, а `FieldRow` ставит два коротких поля в ряд, когда для двух хватает места.

**Ввод карты.** `CardNumberInput`, `ExpiryInput`, `CvcInput`, `CardholderInput`, разложенные
`CardFields`. Они форматируют по мере ввода, не выбрасывая каретку в конец, группируют цифры
так, как их печатает бренд (4-6-5, как только появился префикс Amex), и берут длины из тех же
правил, что и валидатор, — маска и сообщение разойтись не могут. Бренд показывается текстовым
бейджем: логотипы схем — товарные знаки, свои передавайте через `icons`.

**Выбор.** `OptionCardGroup` и `OptionCard` — настоящие радиокнопки, скрытые и стилизованные
через `:has(:checked)`. Стрелки, семантика формы и озвучка достаются от браузера.
`PaymentMethodSelector` — то же самое с платёжными метаданными, и методы приходят от вас: у
кита своего списка нет.

```tsx
<PaymentMethodSelector
  methods={[
    { id: 'card', label: 'Карта', description: 'Visa, Mastercard, Amex' },
    { id: 'transfer', label: 'Банковский перевод', badge: 'Мгновенно' },
  ]}
  value={method}
  onChange={setMethod}
/>
```

**Платёж.** `PaymentStatus` — единственный live-регион на странице: озвучивается то, что
происходит с деньгами, а ошибки полей остаются вежливыми и его не заглушают.
`PaymentButton` показывает спиннер и перестаёт реагировать, пока идёт платёж, но сохраняет
подпись и фокус: подпись, меняющаяся на ходу, уводит цель из-под курсора, а `disabled`
роняет фокус в начало страницы.

`ProcessingState`, `AuthenticationState`, `SuccessState` и `FailureState` — экраны, на
которых платёж заканчивается. Каждый начинается с заголовка и забирает фокус при появлении,
чтобы скринридер начал с ответа. Отмена — это тон `FailureState`, а не пятый экран.

`CheckoutLayout` — это колонка с необязательным `aside` под сумму заказа: на телефоне над
формой, от 48rem — липким блоком сбоку. `ck-panel` — опциональная приподнятая поверхность
для того, что в неё положат.

`ActionFrame` — место, где рисует провайдер. Три варианта, потому что фрейм с полями,
страница банка и QR-код хотят три разных размера:

```tsx
<ActionFrame variant="challenge">
  <PaymentActionHost className="ck-action-host" />
</ActionFrame>
```

## Доступность и граница ответственности

Кит даёт: label и ошибку, связанные с каждым полем; один alert и один status вместо россыпи;
видимое кольцо фокуса на каждом контроле; настоящий таб-паттерн со стрелками; радиогруппы,
достижимые с клавиатуры; цели не меньше 44px; экраны состояний, забирающие фокус.

За вами остаётся: куда уходит фокус при смене ваших роутов, и любые объявления, относящиеся
к вашей вёрстке, а не к платежу. Кит не владеет вашей страницей и сделать это за вас не может.

## Перевод

Любую строку, которую рисует кит, можно заменить. Библиотеки i18n внутри нет и мнения о том,
какую брать, — тоже.

```tsx
<PaymentStatus state={state} messages={{ processing: t('checkout.processing') }} />
<PaymentButton state={state}>{t('checkout.pay')}</PaymentButton>
<SuccessState heading={t('checkout.paid')} />
```

Раннеры в `@checkout-kit/runtime-browser` принимают строки так же — см.
`createBrowserRuntime({ redirect: { frameTitle }, display: { text } })`.

Чего переводить не надо — `PaymentError.message`: это слова эмитента, и именно их покупатель
пересказывает своему банку. Нужна своя формулировка — ветвитесь по `PaymentError.code`, а на
незнакомый код показывайте сообщение как есть.
